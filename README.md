# bybit-bots

11 ботов-стратегий на реальном споте Bybit (по умолчанию DOGEUSDT), каждый
со своим виртуальным балансом 11.98 USDT ≈ 1000 ₽ (бумажная торговля). Все работают одновременно
на одних и тех же котировках — это и есть сравнение вариантов.

Котировки — с публичного REST Bybit mainnet spot (без ключей). Каждая сделка
идёт минимальным ордером биржи (правила лота берутся из instruments-info),
с комиссией 0.1% и проскальзыванием 0.02% за сторону. Решение принимается
один раз на закрытую свечу, исполнение — по текущей цене.
Сделки исполняются только в локальном леджере, реальных ордеров
бот не выставляет.

## Устройство

TypeScript целиком, npm workspaces:

```
server/   NestJS: торговый движок, API и раздача панели
  src/trading/   стратегии, леджер, бот, мета-бот, EngineService (тики)
  src/market/    клиент публичного REST Bybit
  src/storage/   state.json, CSV-логи, дочитывание логов
  src/stats/     GET /api/stats и /api/health, курс ЦБ
  src/telegram/  оповещения
client/   Vue 3 + Vite: панель (StatusBar, SummaryCards, BotsTable, TradesTable)
```

Один процесс: движок раз в минуту делает тик, API отдаёт его состояние и
историю из логов, тот же сервер раздаёт собранную панель (`client/dist`).
Форматы `data/state.json` и `logs/*.csv` — те же, что у прежней JS-версии:
переход на TypeScript не сбросил накопленную статистику.

## Стратегии

1. SMA Crossover (10/30)
2. EMA Crossover (9/21)
3. RSI (14, 30/70)
4. MACD (12/26/9)
5. Bollinger Bands (20, 2σ)
6. Stochastic Oscillator (14, 20/80)
7. Donchian Breakout (20)
8. Mean Reversion (Z-score 20)
9. EMA Ribbon (5/10/15/20/25)
10. Martingale-lite (1% шаг)
11. Adaptive Regime (ER 20) — сама выбирает приём по характеру рынка
12. Авто-выбор лучшей (11) — свой счёт, повторяет сделки стратегии, которая
    больше всех заработала за последние сутки; если в плюсе нет никого,
    стоит вне рынка

Grid (0.5% шаг) лежит в `server/src/trading/strategies/`, но не включена: рядом с
Martingale-lite она ничего не добавляет.

## Запуск

```bash
cp .env.example .env
npm install
npm run build && npm start      # собрать панель и сервер, запустить
```

Разработка — в двух терминалах, панель с горячей перезагрузкой
проксирует `/api` на сервер:

```bash
npm run dev -w server           # NestJS на :3004 (tsx watch)
npm run dev -w client           # Vite на :5173
```

`.env` не требует API-ключей для текущего режима. Поля
`BYBIT_TESTNET_API_KEY`/`SECRET` зарезервированы на будущее, если
понадобится перейти на реальные ордера на тестовой сети.

## Параметры (.env)

- `SYMBOL` — торговая пара (в `.env.example` — `DOGEUSDT`)
- `INTERVAL` — таймфрейм свечей в минутах
- `START_BALANCE` — стартовый виртуальный баланс на бота, USDT
- `START_RUB` — тот же старт в рублях, от него панель считает рублёвую доходность
- `FEE_PCT`, `SLIPPAGE_PCT` — комиссия и проскальзывание за сторону сделки, %
- `ORDER_USDT` — сумма сделки; `0` — минимальный ордер биржи
- `META_WINDOW_CANDLES`, `META_SWITCH_MARGIN_PCT` — окно и порог смены лидера
  у «Авто-выбора»
- `POLL_MS` — частота опроса рынка, `BYBIT_TIMEOUT_MS` — таймаут запроса к бирже

Полный список с пояснениями — в `.env.example`.

## Сессии

Счёт продолжается между перезапусками, но **длительный простой обесценивает
результаты**: позиция, купленная неделю назад, закрывается по сегодняшней цене,
и разрыв рынка приписывается стратегии. Так, после простоя 6–22 августа
цена ушла с 64 542 до 77 290 — и все боты показали «прибыль» 17–22 %,
не сделав ничего.

Поэтому перед осмысленным сравнением сессию начинают заново:

```bash
scripts/new-session.sh
```

Скрипт складывает прежние `logs/*.csv` и `data/state.json` в
`archive/session-<дата>/` и обнуляет счёт. Архив остаётся для разбора.
Если контейнеры запущены, скрипт останавливает их на время переноса и
запускает снова: работающий бот иначе записал бы старый счёт обратно.

## Тесты, хук и выкладка

```bash
npm test                              # Vitest: сервер и панель
npm run typecheck                     # tsc и vue-tsc
git config core.hooksPath .githooks   # один раз: хук перед коммитом
scripts/deploy.sh                     # проверки → код на сервер → пересборка
```

Тесты сервера — от леджера и стратегий до приложения Nest целиком
(поддельная биржа, HTTP-запросы, штатная остановка и продолжение после
рестарта); тесты панели — компоненты и опрос сервера.

Хук `pre-commit` не пускает коммит с лишними пробелами, конфликтными
маркерами, ошибками типов или красными тестами. `deploy.sh` берёт сервер из `DEPLOY_HOST`
(по умолчанию `root@bots.home`) и папку из `DEPLOY_DIR`; `.env`, `data/`,
`logs/` и `archive/` на сервере не трогает — статистика продолжается.

## Docker

```bash
cp .env.example .env
docker compose up -d --build
```

Логи (`logs/equity.csv`, `logs/trades.csv`, `logs/runs.csv`) пишутся в
смонтированную папку `./logs` на хосте — доступны для анализа без захода
в контейнер. Состояние ботов — в `./data/state.json`.

Образ собирается в два этапа: сборка панели и сервера, затем запуск только
с production-зависимостями сервера. Контейнер один.

Остановить: `docker compose down`.

## Telegram

Бот присылает rich-сообщения Bot API 10.3 (`sendRichMessage`): заголовки,
таблицы, спойлеры, сворачиваемые блоки, кнопки и картинку-график.

- **итоги часа** — каждый час с `TELEGRAM_DAY_FROM` до `TELEGRAM_DAY_TO`
  (по умолчанию 9:00–22:00 по `TZ`); ночью отчётов нет. График: цена за сутки
  с отметками сделок и заработок каждого бота. Таблица ботов: счёт, с начала,
  за час; худший за час — под спойлером, сделки за час — в сворачиваемом блоке;
- **итог дня** — в `TELEGRAM_DIGEST_HOUR` (21:00) вместо часового отчёта:
  то же за сутки, плюс лучшая и худшая сделки дня;
- **прибыльную сделку** — сразу, если доходность от `TELEGRAM_MIN_PNL_PCT`:
  сколько она принесла в рублях и долларах после комиссий; ночью без звука;
- **/now** или кнопка «🔄 Обновить» под отчётом — результаты прямо сейчас.
  Бот отвечает только чату из `TELEGRAM_CHAT_ID`;
- при запуске — «на связи» со списком того, что и когда придёт.

График рисуется на сервере (SVG → PNG через resvg). Если Telegram не примет
rich-сообщение, бот отправит то же фото и текст обычными `sendPhoto` и
`sendMessage` — в логе будет причина.

Настройка: создать бота у @BotFather и взять токен, узнать свой chat id у
@userinfobot, вписать оба в `.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`)
и перезапустить контейнер (`docker compose up -d`). Пока токена нет,
оповещения выключены — в логе так и написано.

## Здоровье

`GET /api/health` отвечает `200 {"ok":true,"bot":"running"}`, пока бот
обновляет состояние, и `503` со статусом `stale` (запуск не завершён, но
обновлений больше 5 минут — `STALE_SEC`) или `stopped`. Адрес годится для
Uptime Kuma. Панель в том же случае пишет «не отвечает N мин» вместо
«работает».

`healthcheck` контейнера опрашивает тот же `/api/health`: если бот завис,
`docker compose ps` покажет `unhealthy`.

## Состояние и наработка

Счёт не обнуляется при рестарте: после каждого тика состояние ботов
(баланс, позиция, цена входа, число сделок, реализованный pnl%) пишется
в `data/state.json`, по `SIGTERM` сохраняется финально.

Состояние сбрасывается, если изменились `SYMBOL`, `INTERVAL`,
`START_BALANCE`, рынок (`BYBIT_BASE_URL`/`BYBIT_CATEGORY`), `FEE_PCT`,
`SLIPPAGE_PCT` или `ORDER_USDT` — прежние результаты к новым условиям
не применимы.

### Возобновление после простоя

За время остановки цена уходит, поэтому при первом тике нового запуска:

- позиции переоцениваются по текущей цене (`equity` = кэш + позиция × цена);
- стратегии со внутренней памятью восстанавливаются с контекстом
  (`downtimeSec`, текущая цена, позиция и цена входа из леджера);
  опорный уровень мартингейла после простоя > 30 мин берётся от рынка,
  а в позиции — от фактической цены входа;
- сигналы на покупку/продажу считаются по свежим свечам сразу на старте,
  до начала обычного цикла опроса.

### runs.csv

| Событие | Когда пишется |
|---|---|
| `start` | старт процесса; в `note` — номер запуска |
| `resume` | первый тик после восстановления: простой и разрыв цены |
| `stop` | штатная остановка (`SIGTERM`/`SIGINT`), наработка запуска |
| `crash` | предыдущий запуск оборвался без штатной остановки |

Колонки: `time,event,runId,runUptimeSec,totalUptimeSec,ticks,note`.
`totalUptimeSec` — суммарное время работы за всю историю.

## Формат логов

CSV по RFC 4180: поля с запятыми (имена стратегий вида
`RSI (14, 30/70)`) берутся в кавычки, заголовок пишется один раз при
создании файла (и заново, если файл убрали при работающем боте).
Все боты за тик пишутся в `equity.csv` одной записью с общим временем.
